# Day 1, part 2 — The pipeline that refuses to publish

The whole chain now runs: idea → fact-check → gate → write → rendered JPEGs.
First real output was a German carousel about witch trials, and the
verification stage did exactly what it was built to do.

## The moment it justified itself

Asked for a post about the Middle Ages, it landed on "witch burnings were a
medieval thing" — a genuinely widespread misconception. Then verification went
and checked it, and came back with four caveats:

> *"Don't suggest all executions were burnings. The method varied regionally —
> 'executions for witchcraft' is the defensible term."*

> *"1560–1630 should be framed as a European approximation. There were later
> regional peaks: around 1660 in the Empire, 1661–62 in Scotland."*

Neither of those is a fact-check in the "true/false" sense. They're the
difference between a post that's *technically right* and one that's *actually
right* — which is exactly the failure mode of confident AI content. The draft
that came out used "Hinrichtungen wegen Hexerei" and called 1560–1630 an
approximation, because the writing stage only ever sees claims that survived.

## Provider abstraction, and why it paid for itself in an hour

Built the LLM boundary before the first adapter — `generate()` and
`research()`, no vendor concepts. Felt slightly indulgent at the time.

An hour later: no Anthropic credits, but OpenAI credits available. Swapping
backends was writing one new file and adding one line to a factory. Zero
pipeline changes.

Then added **capability tiers** — `fast` / `balanced` / `deep` — so the pipeline
asks for what a stage *needs* rather than naming a model. Model ids change every
few months; pipeline code shouldn't.

Notably, `deep` does **not** map to the frontier model. On the verification task
the frontier tier took 61 seconds and twelve searches to reach the same verdict
the mid tier reached in 17 and seven. Frontier capacity isn't the bottleneck for
checking whether a documented fact is true.

## Four bugs worth writing down

**1. Sources came back empty on exactly the model we'd use.**
Source extraction read `url_citation` annotations, which is the documented path.
Under strict structured output those come back empty — so a run that opened
twelve pages produced an audit trail of zero. The real URLs live in the
`web_search_call` items' `action` field (`open_page`, `find_in_page`). Found it
by dumping the raw response rather than trusting the docs. On a product whose
entire pitch is "we cite our sources," this one would have been fatal and
silent.

**2. The audit trail recorded the wrong model.**
`generate()` returned `this.model` — the instance default — instead of the model
the tier actually resolved to. So a post generated by the fast tier would be
recorded as having been generated by the balanced one. Caught it because the
smoke test printed the model and it disagreed with the tier I'd asked for.

**3. Reasoning tokens starved the answer.**
Reasoning models bill and count reasoning against `max_output_tokens` but never
return it. Asking for 3,000 tokens produced an `incomplete` response with
nothing in it. Fixed by treating the caller's number as the *answer* budget and
adding the reasoning allowance on top — callers shouldn't have to know how much
a given model thinks.

**4. German broke a word in half.**
The hook rendered as "Hexenverbrennu / ngen". Two causes stacked: `overflow-wrap:
break-word` let the word shatter rather than overflow, so auto-fit never saw an
overflow and never shrank it — and the document said `lang="en"` while the copy
was German, so hyphenation had no dictionary. Now display text uses
`overflow-wrap: normal` and the document declares the niche's language. Result:
"Hexenverbren-nungen", hyphenated at a real syllable boundary. The stress test
even survives *Donaudampfschifffahrtsgesellschaftskapitän*.

## The gate runs before the writing

Deliberate ordering. Writing a full carousel around claims that will be rejected
wastes tokens, but worse, it produces a polished draft that's tempting to wave
through. Failing early keeps the rejection cheap and unarguable.

The gate is mechanical, not model-judged. A model assessing whether its own
output is trustworthy enough to publish isn't a check — and the entire value of
the verification stage would evaporate if a persuasive draft could talk its way
past it.
